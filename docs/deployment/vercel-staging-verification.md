# Vercel Staging Deployment Execution & Verification Runbook (Phase 1.2D)

## 1. Overview & Dual Vercel Deployment Architecture

Callme Yoghurt employs **Dual Vercel Deployments** connected to the unified repository (`Callme-Yoghurt`) to enforce strict security boundaries between the customer-facing storefront and the privileged operations portal:

```
                                [ GitHub Repository ]
                              (phase0/foundation-repair)
                                         |
                     +-------------------+-------------------+
                     |                                       |
                     v                                       v
         [ Vercel Project 1 ]                        [ Vercel Project 2 ]
    `callme-yoghurt-storefront`                      `callme-yoghurt-admin`
                     |                                       |
    NEXT_PUBLIC_APP_MODE=storefront             NEXT_PUBLIC_APP_MODE=admin
                     |                                       |
                     v                                       v
        https://staging.callmeyoghurt.com       https://admin-staging.callmeyoghurt.com
```

## 4. Environment Validation Utility (`src/lib/env-validator.ts`)

Deployment environment integrity is programmatically validated via `validateDeploymentEnv()`:
* **Fail-Closed Guarantee**: In `production` (`NODE_ENV === "production"`), missing required secrets throw an immediate unhandled exception, halting boot or build.
* **Storefront Invariants**: Requires `NEXT_PUBLIC_APP_MODE=storefront`, `ERP_INTERNAL_URL`, `ERP_SERVICE_TOKEN`.
* **Admin Invariants**: Requires `NEXT_PUBLIC_APP_MODE=admin`, `ERP_INTERNAL_URL`, `ADMIN_SESSION_SECRET` (length ≥ 16, recommended ≥ 32).
* **Zero Secret Leakage**: Exception messages list ONLY the names of missing variables (e.g. `ERP_SERVICE_TOKEN`), never their values.

## 5. Security & Isolation Invariants

### 5.1 Cookie Security
All administrative sessions set via `/api/admin/login` enforce:
* `HttpOnly=true` — Inaccessible to client JavaScript (prevents XSS credential theft).
* `SameSite=lax` — Protects against Cross-Site Request Forgery (CSRF).
* `Secure=true` — Transmitted strictly over TLS/HTTPS in production.
* `Path=/` — Scoped across all administrative routes.

### 5.2 Mandatory Security Headers
Every HTTP response generated by Next.js includes hardened headers configured in `next.config.mjs`:
* `Content-Security-Policy`: Restricts scripts to `'self'` and blocks frame embedding (`frame-ancestors 'none'`).
* `X-Content-Type-Options: nosniff`: Prevents MIME-sniffing.
* `Referrer-Policy: strict-origin-when-cross-origin`: Restricts referrer leakage.
* `Permissions-Policy: camera=(), microphone=(), geolocation=(), payment=(), usb=()`: Disables unused browser APIs.
* `X-Frame-Options: DENY`: Prevents clickjacking.
* `Strict-Transport-Security`: HSTS enforced when `ENABLE_HSTS=true`.

### 5.3 Zero Client Bundle Exposure
* Server secrets (`ERP_SERVICE_TOKEN`, `ADMIN_SESSION_SECRET`, `REDIS_URL`) must NEVER be prefixed with `NEXT_PUBLIC_`.
* Automated test `tests/security/deployment-boundary.test.ts` scans all client components and compiled outputs to guarantee zero token leakage.

## 6. Backend Connectivity & BFF Architecture

1. **Proxy Shield (BFF Pattern)**:
   * Client browsers never call Laravel ERP directly. All traffic routes through `/app/api/*`.
   * BFF injects `Authorization: Bearer <ERP_SERVICE_TOKEN>` and forwards requests to `ERP_INTERNAL_URL`.
2. **Circuit Breaker & Timeout**:
   * All BFF routes (`/api/checkout`, `/api/catalog`, `/api/admin/login`, `/api/admin/logout`) enforce an explicit 5000ms `AbortController` timeout.
3. **Sanitized Error Mapping**:
   * Upstream connection errors or timeouts return clean HTTP 502/503 status codes.
   * Internal URLs, internal IP addresses, database connection strings, and stack traces are completely stripped from responses.

## 7. Rollback Process

### 7.1 Instant Vercel Rollback (< 5 Seconds)
1. Open the project dashboard (`callme-yoghurt-storefront` or `callme-yoghurt-admin`) in Vercel.
2. Go to **Deployments**.
3. Select the previous stable deployment.
4. Click `...` > **Instant Rollback**.
5. Edge traffic instantly shifts to the prior immutable build artifact.

### 7.2 Git Revert Rollback
1. Revert the problematic commit on branch `phase0/foundation-repair`:
   ```bash
   git revert <COMMIT_SHA> -m 1
   git push origin phase0/foundation-repair
   ```
2. Automated webhooks trigger new deployment builds on both Vercel projects.
