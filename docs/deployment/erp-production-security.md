# Callme Yoghurt ERP Core — Production Security Architecture & Hardening

> **Enterprise Security Mandate & DevSecOps Compliance**  
> Reference: SOP 04 (Polyglot Database, Auth & Security) & SOP 05 (DevSecOps)

---

## 1. Application Security Configuration

- **APP_DEBUG=false**: Strictly enforced in production. When `APP_ENV=production` and `APP_DEBUG=true`, the container startup validator (`callme:validate-production-config`) aborts boot immediately to prevent stack trace or credential leakage.
- **Zero Secrets Committed**: All cryptographic secrets, database passwords, and API keys are strictly excluded via `.gitignore` and `.dockerignore`. Images are built without baked secrets.
- **Secret Minimum Entropy**:
  - `APP_KEY`: 32 bytes base64-encoded AES key (`base64:...`).
  - `ERP_SERVICE_TOKEN`: Minimum 32 characters (recommended 64 hex chars).
  - `CRM_PII_BLIND_INDEX_KEY`: Minimum 32 characters (recommended 64 hex chars).
  - `CHECKOUT_FINGERPRINT_KEY`: Minimum 32 characters (recommended 64 hex chars).
  - `ADMIN_SESSION_SECRET`: Minimum 16 characters (recommended 64 hex chars).
- **Fail-Closed Principle**: If any critical secret is absent or malformed, requests fail closed (HTTP 503 or 401). No fallback secrets or defaults are permitted.

---

## 2. Network & Boundary Security

- **Architecture Boundary**:
  ```
  [Browser] ──── HTTPS ────> [Next.js BFF (Vercel)] ──── HTTPS + Bearer ────> [Laravel ERP Core]
  ```
  Public browsers NEVER interact directly with transactional ERP endpoints.
- **CORS Hardening**: Wildcard origins (`*`) are disabled in `config/cors.php`. Only public health endpoints (`/api/health`, `/api/ready`) allow cross-origin probes; all transactional routes are blocked from browser cross-origin requests.
- **Trusted Proxy Configuration**: Laravel's trusted proxy middleware is configured to respect only operator-defined reverse proxies (`TRUSTED_PROXIES`), preventing header spoofing via `X-Forwarded-*`.
- **Enforced HTTPS**: `URL::forceScheme('https')` is enforced in production to guarantee that any generated URLs or redirects strictly use HTTPS.

---

## 3. Database Security (PostgreSQL System of Record)

- **Zero Public Port Exposure**: PostgreSQL must never bind to `0.0.0.0` or be exposed to public networks. It communicates exclusively across isolated private Docker networks, VPC subnets, or UNIX sockets.
- **Least-Privilege Database User**:
  - The application connects via a dedicated non-superuser `callme_erp_user`.
  - Disallow `SUPERUSER` or `CREATEDB` privileges for application connection.
- **TLS/SSL Encryption in Transit**: PostgreSQL connection string uses `DB_SSLMODE=prefer` (or `require` for managed cloud providers like AWS RDS / Neon / Supabase).
- **PII Encryption at Rest & Blind Indexing**:
  - Customer personal identifiable information (name, phone number, address) is encrypted at application level using AES-256.
  - Searchable phone queries use HMAC-SHA256 blind indexing (`PhoneBlindIndexService`) with `CRM_PII_BLIND_INDEX_KEY`. Raw phone numbers are never stored in plaintext.
- **Automated Backups**: Nightly encrypted PostgreSQL dumps with 30-day retention. Regular automated restoration verification into a disposable staging database.
- **Migration Safety**: Only non-destructive migrations are permitted (`php artisan migrate --force`). Rollback/reset commands are forbidden in production pipelines.

---

## 4. Ephemeral Infrastructure Security (Redis)

- **Zero Public Port Exposure**: Redis port 6379 must never be accessible from the public Internet.
- **Mandatory Authentication**: Redis runs with `--requirepass <REDIS_PASSWORD>` configured.
- **TLS in Transit**: For cloud Redis providers (e.g. Upstash, AWS ElastiCache), TLS is enforced via `rediss://` scheme.
- **Non-Persistent / Ephemeral Nature**: Redis is strictly used for ephemeral caches, rate limiting, and temporary shipping quote storage (`SHIPPING_CACHE_STORE=redis`). It is **never** the system of record.
- **Fail-Closed Quote Store**: If Redis becomes unavailable, shipping quote generation fails closed rather than silently falling back to insecure local process memory.

---

## 5. Object Storage Security (S3 / R2 / MinIO)

- **Private Buckets Only**: The storage bucket `callme-erp-storage` must have public read access completely disabled.
- **Time-Limited Presigned URLs**: Access to uploaded media (e.g., complaint unboxing videos) is mediated exclusively via short-lived, encrypted presigned URLs generated by `S3ObjectStorageProvider`.
- **Boot Isolation**: Object storage credentials are NOT required for initial ERP boot or checkout operations; they only fail closed when file upload operations are invoked.

---

## 6. Logging, Auditing & Secret Redaction

- **Structured Log Output**: Container logs output to `stderr` / `stdout` for centralized ingestion.
- **Strict Data Redaction**:
  - Never log `ERP_SERVICE_TOKEN`, `BITESHIP_API_KEY`, or `ADMIN_SESSION_SECRET`.
  - Never log passwords, credit card numbers, or full payment payloads.
  - Never log raw customer PII.
  - Preserve `request_id` and domain identifiers (`order_id`, `order_number`) for traceability.
- **Immutable Admin Audit Logging**: All administrative actions (logins, logouts, lockouts, product creation/updates, inventory adjustments) are written to PostgreSQL `admin_audit_logs` with timestamps, actor IDs, and IP addresses.

---

## 7. Operational Access & Credentials Lifecycle

- **Admin Provisioning**: Administrative users are created exclusively through the authenticated CLI command `php artisan callme:create-owner`, which hashes passwords with Argon2id and records an audit log.
- **Token Rotation**:
  - `ERP_SERVICE_TOKEN` rotation procedure: Update Vercel BFF environment variable and ERP environment variable simultaneously, then restart both services.
  - Rotating `CRM_PII_BLIND_INDEX_KEY` requires a controlled database re-indexing script (scheduled maintenance).
- **Rate Limiting**:
  - Rate limiting is enforced at BFF layer and Nginx level (30 requests/second burst 50 for `/api/`).
  - Admin login endpoints enforce consecutive failure lockouts (account lock after repeated failed password attempts).
